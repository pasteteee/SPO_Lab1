# ЛР1. Метрики Холстеда — объяснение, план защиты, вопросы

Папка лабораторной:

- `perl/students.pl` — анализируемая программа на Perl (97 строк, консольная, все основные операторы, четыре пользовательские подпрограммы).
- `src/HalsteadMetrics.sln` — программа-парсер на Microsoft C++ (C++/CLI, Windows Forms, .NET Framework 4.8). Готовый exe: `src/HalsteadMetrics/bin/Release/HalsteadMetrics.exe`.
- `report/` — отчёт `Отчет_ЛР1_Метрики_Холстеда.docx`, скрипт его сборки и скриншот.

## 1. Что такое метрики Холстеда и зачем они

Метрики Холстеда — это **метрики размера программы**. Они основаны только на тексте программы: программу рассматривают как последовательность **операторов** (действий) и **операндов** (данных). Ничего не запускается и не компилируется, нужен только исходник. Их предложил Морис Холстед в 1977 году; идея — по количеству «слов» программы оценить её объём, сложность и трудоёмкость.

Простейшие метрики размера — число строк (LOC) и число операторов. Холстед пошёл дальше и разделил все лексемы программы на два класса:

- **Операнд** — то, над чем выполняются действия: переменные и константы (числа, строки, регулярные выражения).
- **Оператор** — то, что выполняет действие: знаки операций (`+`, `=`, `==`, `.`), ключевые слова управления (`if…elsif…else`, `while`, `foreach`), имена функций и подпрограмм (`print`, `push`, `average`), разделитель `;`, пары скобок.

## 2. Определения и формулы (знать наизусть)

### Шесть базовых метрик (определяются прямо по тексту)

| Обозначение | Название | Как получить |
|---|---|---|
| η1 (эта-один) | Словарь операторов | Число **уникальных** операторов программы |
| η2 | Словарь операндов | Число **уникальных** операндов программы |
| N1 | Общее число операторов | Сколько раз всего встретились операторы (с повторами) |
| N2 | Общее число операндов | Сколько раз всего встретились операнды (с повторами) |
| f1j | Частота j-го оператора | Число вхождений j-го оператора, j = 1 … η1 |
| f2i | Частота i-го операнда | Число вхождений i-го операнда, i = 1 … η2 |

Связь между ними (это и есть «таблица 2» в методичке и в нашей программе):

- N1 = Σ f1j (сумма частот всех операторов) — сумма столбца f1j;
- N2 = Σ f2i (сумма частот всех операндов) — сумма столбца f2i.

### Три расширенные (производные) метрики

| Метрика | Формула | Смысл |
|---|---|---|
| Словарь программы | **η = η1 + η2** | Сколько всего разных «слов» использует программа |
| Длина программы | **N = N1 + N2** | Сколько всего «слов» в программе с повторами |
| Объём программы | **V = N · log2 η** | Сколько бит нужно, чтобы записать программу: каждое из N слов кодируется log2 η битами (столько бит нужно, чтобы различить η слов) |

Пример из методички (программа на Паскале, синус через ряд): η1 = 14, N1 = 33, η2 = 7, N2 = 28 → η = 21, N = 61, V = 61 · log2 21 ≈ 61 · 4,39 = 268.

Наша программа (`students.pl`): η1 = 58, N1 = 225, η2 = 76, N2 = 176 → η = 134, N = 401, V = 401 · log2 134 ≈ 401 · 7,066 = 2833,50 ≈ 2834.

### Другие метрики Холстеда (в задании не требуются, но могут спросить «а какие ещё есть»)

- Теоретическая (потенциальная) длина: N^ = η1 · log2 η1 + η2 · log2 η2 — какой длины программа «должна быть» при данном словаре.
- Уровень программы: L = (2 / η1) · (η2 / N2) — чем ближе к 1, тем лаконичнее программа.
- Сложность (трудность): D = 1 / L = (η1 / 2) · (N2 / η2).
- Интеллектуальное содержание: I = L · V.
- Усилия (работа) на написание: E = V / L = D · V (в «элементарных различениях»).
- Время программирования: T = E / 18 секунд (18 — число Страуда, столько различений в секунду делает человек).
- Ожидаемое число ошибок: B = V / 3000 (иногда B = E^(2/3) / 3000).

Для нашей программы: L = (2/58)·(76/176) ≈ 0,0149; D ≈ 67,2; E = D·V ≈ 190 300; T ≈ 10 570 с ≈ 2,9 ч; B ≈ 0,94.

## 3. Правила подсчёта для Perl (наша «таблица 1»)

Методичка даёт правила для Паскаля. Мы перенесли их на Perl:

**Операторы**

| Группа | Что считаем | Замечание |
|---|---|---|
| Арифметика | `+ - * / % **` | Унарный и бинарный минус — один и тот же оператор `-` (как `–` в примере методички: `–vs` и `n – 1` считались вместе) |
| Строковые | `.` (сцепление), `x` (повторение) | `x` — оператор только если слева операнд: `"-" x 40` |
| Сравнения | `== != < > <= >= <=>` и строковые `eq ne lt gt le ge cmp` | |
| Логические | `&& \|\| ! // and or not xor` | `//` — «значение по умолчанию, если undef» |
| Присваивания | `= += -= *= /= .= //= \|\|= &&=` — каждое отдельный оператор | В методичке `:=` — отдельный оператор |
| Инкремент | `++ --` | |
| Тернарный | `? :` — один оператор | |
| Привязка к регулярному выражению | `=~ !~` | |
| Разделитель операторов | `;` | Как в методичке. Точки с запятой внутри заголовка `for (a; b; c)` — часть оператора `for`, не считаются |
| Скобки | `( )` — группировка выражения; `[ ]` — индекс массива; `{ }` — обращение к элементу хеша | Пара скобок = один оператор, как в методичке. Скобки, принадлежащие оператору (условие `if (...)`, аргументы `print(...)`, тело `foreach (...) { }`), отдельно НЕ считаются |
| Управляющие | `if…elsif…else`, `unless…else`, `while`, `until`, `for`, `foreach`, `do…while`, `last`, `next`, `redo`, `return` | Несколько служебных слов одного оператора = один оператор (как `If…Then…Else` в методичке). Постфиксная форма `print "x" if $a;` — тот же оператор `if…elsif…else` |
| Объявления | `my`, `our`, `local`, `sub` | `sub` — объявление подпрограммы; имя при объявлении не считаем, как заголовок процедуры в Паскале |
| Функции | `print`, `printf`, `push`, `keys`, `scalar`, `join`, `split`, `length`, `substr`, `uc`, `chomp`, `exists`, `delete`, `shift`, … и **пользовательские** `average`, `grade_label`, `factorial`, `normalize_name` | Имя функции = оператор (как `Readln( )` и `abs( )` в методичке) |
| Ввод | `<>` — чтение строки (`<STDIN>`) | `STDIN` при этом операнд (дескриптор) |
| Регулярные | `s///` (замена), `tr///` (транслитерация) | Шаблон и строка замены — операнды |

**Операнды**

- переменные: `$x`, `@arr`, `%h`, `$_`, `@_`; элемент массива `$arr[0]` — это операнд `@arr` плюс оператор `[ ]`; элемент хеша `$h{k}` — операнд `%h` плюс оператор `{ }`;
- числовые константы: `0`, `4`, `0.0001`;
- строковые константы: `"Name"`, `"\n"`, `"$line\n"` — строка целиком считается **одной** константой, переменные внутри строки не выделяются (упрощение; так же printf-строка в Си считается одной константой);
- регулярные выражения: `/^\d+$/`, `/ /` — константа-шаблон;
- слова-ключи хеша и дескрипторы: `Ivanov` в `Ivanov => …` (Perl сам берёт в кавычки), `STDIN`.

**Не считается вообще**

- комментарии `# …` и строка `#!/usr/bin/perl`;
- директивы `use strict; use warnings;` (аналог заголовка программы и раздела описаний в Паскале — методичка велит анализировать только раздел операторов);
- запятая `,` и «жирная запятая» `=>` — разделители списка (в таблице 1 методички запятой нет: в `Writeln (x, y, eps)` считался только `Writeln ( )`);
- `else`, `elsif` — части оператора `if`; `while` в конце `do { } while` — часть оператора `do…while`;
- метки (`OUTER:`) — по методичке не относятся ни к операторам, ни к операндам.

## 4. Как устроена программа-парсер

Проект `src/HalsteadMetrics` — три файла с кодом:

1. **`PerlAnalyzer.h / .cpp`** — ядро на обычном C++. Класс `PerlAnalyzer` читает текст по одному символу (лексический анализ) и сразу классифицирует лексемы:
   - `readWord()` — слова: ключевые слова, функции, квази-кавычки (`s///`, `qw()`), слова перед `=>`;
   - `readNumber()`, `readString()` — константы;
   - `readVariable()` — `$x @a %h &f`, элементы массивов и хешей;
   - `readPunct()` — знаки операций (сначала длинные `<=>`, `**=`, потом короткие), скобки, `;`, регулярные выражения `/…/`, чтение `<STDIN>`, heredoc;
   - `finalize()` — группировка одинаковых лексем, сортировка по частоте, расчёт метрик.

   Два ключевых приёма:
   - флаг **`prevIsTerm`** («предыдущая лексема — операнд?») решает неоднозначности Perl: `/` после операнда — деление, иначе — начало регулярного выражения; `%` после операнда — остаток от деления, иначе — сигил хеша; `x` после операнда — повторение строки, иначе — имя;
   - **свёртка скобок**: после `if`, `while`, `print`, `my` ближайшая `(` помечается как «часть предыдущего оператора» и отдельно не считается; то же для `{` после `) `, `else`, `sub имя`, `sort`. Для этого ведутся два стека скобок, в которых хранится «роль» каждой открытой скобки.

2. **`MainForm.h`** — окно Windows Forms (C++/CLI): редактор кода слева, таблица 2 справа, три карточки расширенных метрик внизу. Форма берёт текст из `RichTextBox`, вызывает `PerlAnalyzer::analyze()` и раскладывает результат по `DataGridView`. Пересчёт происходит автоматически через 350 мс после любого изменения текста (таймер), а щелчок по строке таблицы подсвечивает жёлтым все вхождения этого оператора/операнда в коде.

3. **`MainForm.cpp`** — точка входа `main`: включает DPI-awareness, запускает `Application::Run`. Если передать путь к `.pl` в командной строке, файл откроется сразу.

Почему C++/CLI: задание требует графический интерфейс, а Windows Forms в Visual Studio — самый быстрый способ его сделать на C++. Синтаксис C++/CLI: `ref class` — класс .NET, `^` — управляемый указатель, `gcnew` — создание объекта в куче .NET (удаляет сборщик мусора), `L"текст"` — строка UTF-16. Ядро анализатора при этом — обычный C++ (`std::wstring`, `std::vector`, `std::map`), его можно собрать и без .NET (так собирается консольный тест).

## 6. Заготовки изменений для демонстрации

| Что сделать в редакторе | Что должно измениться |
|---|---|
| Дописать строку `$counter = $counter + 1;` | N1 + 3 (`=`, `+`, `;`), N2 + 3 (`$counter` ×2, `1`); η1 и η2 не меняются, так как все эти лексемы уже были |
| Дописать `my $z = 100;` | Новый операнд `$z` и новая константа `100`: η2 + 2, N2 + 2; N1 + 3 (`my`, `=`, `;`) |
| Дописать `print "Hello\n" if $z > 50;` | `print`, `if…elsif…else`, `>`, `;` → N1 + 4; строка `"Hello\n"`, `$z`, `50` → η2 + 2 (строка и 50 новые), N2 + 3 |
| Удалить любую строку с `;` | Число `;` уменьшится на 1, N1 и N уменьшатся |
| Заменить `foreach` на `for` | В таблице `foreach` станет 1, `for` станет 2 (это разные операторы, как `For…To…Do` и `For…Downto…Do`) |
| Дописать `$k **= 2;` | Появится новый оператор `**=`: η1 + 1 |
| Закомментировать строку (`#` в начале) | Все её лексемы исчезнут из таблицы |

После правки таблица пересчитывается сама (флажок «Пересчитывать при вводе»), либо нажать «Рассчитать».

## 7. Вопросы, которые могут задать, и ответы

1. **Что такое метрики Холстеда?** Метрики размера программы, основанные на подсчёте операторов и операндов в исходном тексте.
2. **Назовите шесть базовых метрик.** η1 — словарь операторов (число уникальных операторов), η2 — словарь операндов, N1 — общее число операторов, N2 — общее число операндов, f1j — частота j-го оператора, f2i — частота i-го операнда. N1 = Σ f1j, N2 = Σ f2i.
3. **Назовите расширенные метрики и формулы.** Словарь η = η1 + η2; длина N = N1 + N2; объём V = N·log2 η.
4. **Почему в объёме логарифм по основанию 2?** log2 η — число бит, нужное, чтобы закодировать одно из η слов словаря; умножаем на число слов N — получаем объём программы в битах.
5. **Что такое операнд? оператор?** Операнд — переменная или константа. Оператор — знак операции, присваивание, разделители `;` (и `.` в Паскале), пара скобок, управляющий оператор, составной оператор, имя процедуры/функции.
6. **Почему `if…elsif…else` — один оператор?** По методичке несколько служебных слов одного оператора (`If…Then…Else`) считаются одним оператором: они образуют одну конструкцию.
7. **Почему скобки после `print` или `if` не считаются?** Они принадлежат оператору (вызову функции или условию), как в примере методички `Readln ( )` и `abs( )` считаются вместе со скобками, а оператор `( )` — только скобки, выделяющие подвыражение.
8. **Почему запятая не оператор?** В таблице операторов методички запятой нет; в примере `Writeln (x, y, eps)` запятые не считались. Это разделитель списка.
9. **Почему `my` — оператор?** Это действие объявления переменной, ключевое слово языка; аналогично в анализаторах для Си `int`, `float` считают операторами. Директивы `use strict` не считаем, потому что методичка велит анализировать только раздел операторов, а `use` — аналог заголовка/описаний.
10. **Как программа отличает деление от регулярного выражения?** По предыдущей лексеме: после операнда или закрывающей скобки `/` — деление, иначе — начало регулярного выражения. Так же различаются `%` (остаток / сигил хеша) и `x` (повторение / имя).
11. **Что такое `$grades{$name}` в терминах Холстеда?** Операнд `%grades` (хеш) и оператор `{ }` (обращение к элементу), внутри — операнд `$name`.
12. **Как считается `do { … } while (…)`?** Один оператор `do…while`, как `Repeat…Until` в Паскале.
13. **Что будет, если в программе ошибка синтаксиса?** Парсер лексический, он не проверяет синтаксис — посчитает лексемы как есть. Это нормально для метрик размера.
14. **Что не считается?** Комментарии, директивы `use`, запятые, `else`/`elsif`, метки, имя подпрограммы при объявлении.
15. **Чем V отличается от N?** N — число слов, V — число бит: V учитывает ещё и размер словаря (чем больше разных слов, тем больше бит на слово).
16. **Как менялись бы метрики, если переписать программу короче?** Уменьшатся N1, N2, N и V; η может почти не измениться. Уровень L = (2/η1)(η2/N2) вырастет — программа станет «выше уровнем».
17. **Какие ещё метрики Холстеда есть?** Потенциальная длина N^, уровень L, сложность D = 1/L, усилия E = V/L, время T = E/18, число ошибок B = V/3000, интеллектуальное содержание I = L·V.
18. **Зачем это на практике?** Оценка объёма и трудоёмкости кода, сравнение реализаций, прогноз числа ошибок, входные данные для моделей стоимости.
19. **Почему строка `"Total = $total"` — один операнд?** Принято упрощение: строковый литерал — одна константа; выделять переменные внутри строки — уже семантический разбор. Это оговорено в отчёте.
20. **На чём написана программа и почему?** Microsoft C++ (Visual Studio 2026, C++/CLI, Windows Forms): требуется графический интерфейс; ядро анализатора — обычный C++, интерфейс — .NET. Сборка: `HalsteadMetrics.sln`, Release x64.
